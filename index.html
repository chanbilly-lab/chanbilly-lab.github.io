01 / Document workflow

DocFlow

A serverless application project for requesting documents, recording submissions and supporting a human review decision without losing the history behind it.

Define requirements→Submit documents→Human review→Decision record

Implementation focus

  • Stable requirements. Immutable versions keep a request tied to the requirements the submitter actually received.
  • Controlled document access. Private upload handling and explicit review steps keep submission and approval separate.
  • Traceable operations. Audit records and an outbox support asynchronous notifications without treating a queued event as delivery.
  • Full-stack implementation. Python services, a React/TypeScript interface and Terraform infrastructure definitions.

Delivery status

The frontend demonstration uses synthetic data and in-memory state. It is separate from the backend.

Five limited AWS backend journeys were completed historically. Remaining cloud acceptance work is unfinished; the cloud resources have been retired.

This is a development case study. There is no live service or production-readiness claim.

September 2026 demonstration screenshots: all names, organisations and case identifiers are fictional. The interface uses in-memory state and is not connected to real authentication or upload APIs. It is not a live cloud application. Project source is private; a code walkthrough can be arranged on request.

02 / Evidence-based advising

Admissions Advisory Agent

A modular monolith designed to connect student information to explicit requirements and evidence, while keeping missing information visible.

Student profile→Program options→Eligibility→Evidence→Draft plan

Implementation focus

  • Deterministic decisions. Four distinct eligibility states: eligible, ineligible, conditional and unknown. Missing grades remain unknown without a documented deferral policy.
  • Source-linked reference data. A local reference batch contains three 2026 Zhejiang provincial cutoff records, with a source and review trail. These are not university admission thresholds.
  • Explicit selections. School and program search replaces manual identifiers in the source implementation. The formal directory is still empty.
  • Practical architecture. Vue 3/TypeScript/Vite, Python/FastAPI/Pydantic and PostgreSQL, with a replaceable model interface.

Delivery status

The synthetic M0 core flow has been run locally. Other completed source tasks do not imply completed runtime acceptance.

Annual update scheduling only creates pending collection/review requests and is disabled by default. Live model calls and public service remain off.

No admission probability estimates, automatic applications or fabricated missing school data.

The public case study describes a local development project. It does not offer personalised admissions advice or nationwide data coverage. Project source is private; a code walkthrough can be arranged on request.
